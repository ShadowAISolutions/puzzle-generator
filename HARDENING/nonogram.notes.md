# Nonogram — notes the generated hardening report cannot carry

`HARDENING/nonogram.md` is regenerated by `tools/harden.mjs` on every run and says so. This file
is written by hand and explains two numbers in it that would otherwise look like something
missing.

## `removals_from_minimal_instances: 0`

The mutation pass has two halves. The broad half takes random unique instances, mutates them, and
demands that the solver and the reference never diverge; for nonogram that half ran 702 checks and
is where the pass's value is. The strict half takes a **minimal** instance and demands that
removing any one unit of given information breaks uniqueness. It reports zero for this family, and
that is correct rather than skipped.

A sudoku or a binairo presents a subset of a finished grid, so a dig can ask which givens are
load-bearing and minimality is a real claim about that dig. A nonogram presents its clues, and the
clues are a **function** of the solution: there is no subset to choose and nothing to leave out.
Every unique nonogram is already minimal, trivially.

There is also no weakening to test with. A line's clue names its run lengths exactly, so the sets
of lines satisfying two different clues are disjoint. No clue is weaker than another — changing a
run does not enlarge the solution set, it replaces it, which is why a mutated nonogram can
perfectly well still be unique with a different solution. Measured over 1,502 mutants of 25 unique
instances: 0.4% stayed unique, every one with a different solution, and the two solvers never
disagreed.

`weakenings` in `solver/nonogram/index.mjs` therefore returns the empty list for a minimality
claim. The alternative considered and rejected was to draw instances until one turned up whose
mutants all happened to break uniqueness — about 80% of them do — which would have made the pass
report a healthy number while testing nothing. That is the failure mode the anti-drift rules
exist to prevent, so the honest zero is what is recorded.

## `bands: {"1": 24, "2": 8, "3": 9, "4": 1}` in the fixture set, and no band 5

Band 5 means bounded search is required. **No band-5 nonogram has been observed at any supported
shape.** A hypothesis on a single cell, worked out with full line reasoning, resolves every unique
nonogram measured so far. Band 4 exists but is scarce: roughly one hill climb in thirty at 12×12.

This is recorded rather than engineered around. `tools/make_plans.mjs` queues no band-5 nonogram
plan, because a plan that cannot be met is a plan that wastes a batch. If one ever appears, the
fixture build attempts band 5 at every shape on every run and will pick it up.

## The ladder was rebuilt once, before anything was frozen

The first ladder was the obvious one — overlap, run bounds, full line solving, cell contradiction
— and it had a dead rung. Sweeping rows and columns alternately recovers everything full line
solving knows that run bounds does not, so of 40 grids run-bound propagation could not finish,
full line solving finished **none** and cell contradiction finished all 40. Band 3 would have been
a label no puzzle could earn.

The ladder that was frozen separates by how hard the solver may think inside a hypothesis, which
is a distinction the row-and-column iteration does not erase. `solver/nonogram/bands.json` carries
the same explanation in its `ladder_note`, and `line.mjs` keeps its own three line tiers, which
are exact and validated; the grid ladder uses the first and the third.
